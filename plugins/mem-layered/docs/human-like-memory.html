为什么⑦ 不做（v1.5.0 后撤掉）

⑦ 的原案是给碎片权重叠一层"情绪 / 显著性"乘数（感叹号密度、人称密度、承诺与期限词）。 实现过一版（默认关），随后撤掉，理由是它会用启发式猜测悄悄改变整套记忆的取舍：

  • 感叹号多不等于重要 —— 震惊体、灌水、吵架都满是感叹号。
  • "我/你"密度高也不等于跟自己相关 —— 恰恰是寒暄最常这么说话。
  • 真正该判"重要"的是可执行信号（提问、约定、待办、链接）， 而这些 weightOf 早已覆盖，且是可判定的，不是猜的。
  • 寒暄与日常恰恰是记忆的主体，一旦系统性压低，记忆会慢慢只剩"高光时刻"。

现在 weightOf 只认可判定的结构信号，J9 / L3 两条反向断言守着这条边界 —— 谁想加回来，测试先红。

一句话诊断

现在的插件是 Ebbinghaus 1885 的教科书版：一条全局指数衰减 + 一个常数命中增益。 它缺的不是功能，而是三个变量 —— 间隔、稳定性、可检索的线索。 其中"间隔"的缺失最要命：插件根本看不见它。

二、最要命的那一条：插件看不见"间隔"

做了一组对照：同样让一块被命中 8 次，只改命中节奏 —— A 是每 30 分钟一次（一个下午被反复注入），B 是每 30 天一次（八个月里陆续想起）。

（"天数"= 最后一次命中之后还能活多久，跨过 0.25 淘汰阈值即被删。）

当前模型下 A 和 B 的结果一模一样：都是 score 封顶 3、半衰期都是 45 天、命中后都只能再活 162 天。 也就是说，"半小时刷 8 次"和"八个月里想起 8 次"在插件眼里毫无区别 —— 而人恰恰相反。

附带发现：一个正反馈环

lib/recall.js:139 的 recallForPrompt（每轮自动注入用的）调 search 时没传 feedback:false，所以默认的 feedback=true 生效 —— 每轮自动注入也在给块加分。于是： 

块被注入 → score ×1.15 → 排名更高 → 更容易被再次注入 → score ×1.15 → …（8 次即封顶 3）

而自动注入的触发条件是"本轮聊到了相关话题"，是个很弱的信号。 结果就是：某个下午聊热了的话题，会被钉成近乎永久的记忆（封顶后要 161 天才会掉下阈值）。 这在人身上不会发生 —— 人对"上周三下午聊了三小时"的记忆是会淡的。

三、建议做的七件事

P0① 命中增益改成"间隔依赖"

把常数增益换成间隔的函数。这不是新发明 —— 它是现有公式的严格推广： 间隔正好等于稳定性 S 时，退化成现在的 1.15，所以老配置不用改。 

// 现在：增益与间隔无关
score = clamp(score × 1.15, 0.05, 3)

// 建议：间隔越久，想起来越"值钱"
r     = log2(1 + 间隔天数 / S)              // 间隔 = now - lastHitAt
score = clamp(score × (1 + (hitBoost-1) × r), 0.05, 3)
  • 间隔 ≈ 0（半小时内被反复注入）→ 增益 ≈ 1.00，自动掐断上面那个正反馈环
  • 间隔 = S（按半衰期节律想起）→ 增益 = 1.15，与现状一致
  • 间隔 = 4S（很久没想突然想起）→ 增益 ≈ 1.35，符合"想了好久才想起来的最牢"

改动面：store.js markHit() 一个函数；需要 lastHitAt（已有）。风险：极低，且天然向后兼容。

P0② 每块自己的稳定性 S，取代全局半衰期

这是"人类化"里收益最大的一条。人的遗忘速度不是一个全局常数 —— 反复成功提取的东西，衰减本身就变慢了。 

// 现在：全局常量，每块一样
halfLife = 45 天

// 建议：每块一个 S，命中后按间隔增长
S = min(S_max, S × (1 + a × log2(1 + 间隔天数 / S)))    // a ≈ 1.0，S_max ≈ 3650 天
衰减 = 0.5 ^ (t / S)

每 30 天想起一次，S 的增长轨迹：

命中次数0135810
S（天）4578153233356439

改动面：state.json 的块元数据多一个 S 字段；effectiveScore 与 markHit 各改几行。 向后兼容：老块没有 S 就回落到全局默认。风险：低。 注意 S_max 必须设上限，否则理论上能长到永不衰减（那就不像人了）。

P0③ 被动注入与主动检索分开计权

人是"主动想出来"才记得牢，被动重看几乎不长记性（测试效应）。 现在两者都是 markHit ×1.15。

  • 主动检索（模型调 memory_search、或每轮自动检索命中）→ 全额增益 + 增长 S
  • 被动注入（块被注入进提示词、但没人真的去用它）→ 只刷新 lastHitAt，不加分、不涨 S

① 和 ③ 有重叠（间隔近 → 增益自然小），但显式区分更干净，而且能让 stats.json 回答一个真问题：主动检索和被动注入，哪个的留存更高。

改动面：recall.js 的 feedback 从布尔改成三态（off / touch / full）。风险：低。

P1④ 衰减形状从纯指数改成 Weibull

// 现在
0.5 ^ (t / S)
// 建议（q ≈ 0.7；q = 1 就退回现在的行为）
0.5 ^ ((t / S) ^ q)
距上次命中15 天45 天90 天180 天360 天
现在（指数）0.7940.5000.2500.0630.050
建议（q=0.7）0.7250.5000.3240.1610.051

半衰期语义不变（t = S 时仍是 0.5），所以老配置不用动。 形状变成"早期掉得更快、后面拖一条长尾" —— 这正是人类保持率的实测形状。

改动面：store.js:343 一行 + 一个设置项 decayShape（默认 0.7）。风险：低。

P1⑤ 淘汰时留"梗概墓碑"

人不会把一段经历彻底抹掉，只会丢掉细节、留下"大概是什么事"； 而且再学时比全新学快得多（节省效应 / savings）。现在 forgetSweep 是彻底删除。

  • 淘汰时写一条 ≤40 字的梗概（关键词 + 一句摘要 + 命中次数 + 时间范围）进 gist.json，永不淘汰（或超长 TTL）
  • 检索时梗概作为低权重候选参与
  • 命中梗概 → 按时间范围从 messages/ 快速重建块 —— 这就是节省效应的工程版

这条特别适合本插件，因为 messages/ 是只读的完整真相源，重建的成本只是读文件。 当前"淘汰 = 彻底失忆"，加上梗概就变成"记得有这回事，细节要翻档案"——更接近人。

改动面：store.js forgetSweep + 新的 lib/gist.js。风险：中（新文件 + 检索链路要接梗概）。

P1⑥ 多线索检索：把"在场的人"当线索

人回忆靠多重线索（编码特异性）。插件现在只用文本 + 时间词，但 index.js 的 before-context 已经把 personIds 采集好了（pending.js 也在用）， 只是没喂给检索。 

命中块若包含"当前在场的人"  →  ×1.3
同一话题连续几轮            →  把上一轮注入过的块也当线索（跨轮档案里已有）

改动面：recall.js 的排序阶段。风险：低，纯本地判断、零 token。

放弃⑦ 显著性与情绪加权

人对情绪强烈、与自己相关的事记得牢得多（情绪增强记忆 / 自我参照效应）， 现在所有块出厂 score = 1。

原案是用感叹号密度、人称密度、承诺与期限词给碎片权重叠一个 1.0~1.8 的乘子。 实现过一版（默认关），随后撤掉。撤掉的理由见上方说明，简短版：

  • 感叹号多 ≠ 重要（震惊体、灌水、吵架都满是感叹号）。
  • "我/你"密度高 ≠ 跟自己相关（寒暄最常这么说话）。
  • 该判"重要"的可执行信号（提问、约定、待办、链接）weightOf 早已覆盖，且可判定。
  • 系统性压低寒暄与日常，记忆会慢慢只剩"高光时刻" —— 而那恰恰是最不该发生的失真。

结论：这个插件不做情绪判断。weightOf 只认可判定的结构信号， 并由 J9 / L3 两条反向断言守住边界。若将来真要做，也应该做成 可选的离线整理任务（下方"不建议做的三件事"第一条），而不是塞进建块主流程。

四、不建议做的三件事

看起来不错为什么不做
让模型写记忆摘要 / 判重要性 每一轮都要额外调 LLM，成本和延迟都实打实。这个插件从第一天起就是"零额外调用、纯本地确定性"。 真要做，也该做成可选的离线整理任务（每天一次），而不是塞进主流程。
重建式回忆（让模型改写旧事） 人确实会重构记忆并出错，但对一个要发言的机器人来说，编造旧事是灾难性的。 保持"原文片段 + 时间戳"这条底线。
把遗忘做成随机 / 噪声 人类遗忘有随机性，但对机器人没有好处，只会让行为不可预测、难排障。

五、落地顺序

第 1 批（①②③，都在 store.js / recall.js，一起改）

这三条互相咬合：②给出 S，①用 S 算间隔比，③决定谁有资格调用它们。 改完按现有的 F/G 组思路补回归断言，重点钉住三条： 密集命中不该把块顶到封顶；间隔命中应该把 S 抬高；feedback:off 时 score 与 S 都不动。

第 2 批（④⑤⑥）：衰减形状、梗概墓碑、多线索检索。相对独立，可以分开验证。

另加一批（v1.5.0 实际做的）：检索结果多样性 MMR、墓碑复活失败退避、索引懒自愈 —— 纯健壮性与去重，不涉及任何"猜"。

第 3 批（⑦）：显著性，默认关，先观察误判率。 已取消。启发式误判会把记忆带向"只记高光"，而寒暄与日常才是记忆的主体。这条不做。

但最重要的一件事不是改代码

上面所有数字都是公式推演，不是实测。插件到现在还没装进宿主跑过真实流量 —— 连"自动检索的命中率是多少"、"真实的想起间隔分布长什么样"都还不知道。 而 ①②④ 的参数（a、q、S_max）都该按真实分布来定。

建议：先把现在的版本装进去跑两周，拿到真实的间隔分布和命中率，再动这几个参数。 否则就是在猜。
